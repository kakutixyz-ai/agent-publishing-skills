## Trigger Context

Triggered by mentions of 'Layers', 'layers.to', or 'design engineering portfolio platform'.

## Language

**Primary language:** English (US/international technical English). The platform's core audience, curators, and featured projects are all English-speaking design engineers. All project titles, descriptions, and tags must be in English.

## Good Fit

- Projects with a strong visual outcome — 3D scenes, WebGL demos, interactive data visualizations, generative art, or complex animations.
- Technical craft showcases where the primary value is in the execution (shaders, physics simulations, real-time rendering).
- Design engineering experiments that push browser capabilities (e.g., custom layout engines, GPU-accelerated interactions).
- Open-source tools or libraries with a visible demo page (e.g., a React animation library with a live playground).
- Portfolio pieces for design engineers, creative developers, and front-end architects seeking professional visibility.

## Poor Fit

- Backend-only projects (APIs, databases, server infrastructure) with no visual interface.
- Mobile apps that cannot be demonstrated in-browser or via a high-quality video capture.
- Text-heavy content (blog posts, documentation, tutorials, whitepapers) — Layers is for outcomes, not explanations.
- Branding or logo design without interactive or animated elements — static images perform poorly.
- Product launches for non-visual SaaS tools — the audience expects to see craft, not feature lists.

## Format And Style Notes

- Titles are technical, not poetic. State the technology and the effect, not a creative name.
- Descriptions are 1-3 sentences max. No paragraphs, no headings, no lists. State what it is, the core challenge, and the tools.
- Tags are specific and tool-focused. Use 3-5 tags naming the exact libraries, frameworks, or tools.
- Cover media must be a video or GIF. Auto-play is the default. Static images are a weakness.
- Avoid text in images. The audience reads code, not slides. Do not include screenshots of documentation, code editors, or presentation decks.
- Link to code, don't embed it. The description field supports links but not code blocks. Provide a GitHub or CodePen URL.
- Aspect ratio matters. Use 16:9 or 4:3 for cover media. Vertical videos, square crops, or extreme panoramas break the grid layout.
- Process is invisible. Layers is for the finished outcome, not the process. Do not show wireframes, sketches, or behind-the-scenes work.

## Tone

Present the finished craft with technical precision; let the execution speak, not the explanation.
