## Trigger Context

Triggered by mentions of 'Dribbble', 'UI portfolio', 'design shots', 'visual design community'

## Language

- **Primary language:** English (US). All shot titles, descriptions, and tags must be in English to maximize discoverability among recruiters, design leads, and the global design community.
- **Multilingual strategy:** Non-English descriptions drastically reduce reach. If you must include another language, place it after the English description in parentheses. Avoid long paragraphs in any language — text is secondary to the image.
- **Tone:** Professional but casual. Short, benefit-oriented sentences. Keyword-rich for search (e.g., "SaaS dashboard", "dark mode UI", "mobile e-commerce").

## Good Fit

- Your project has a polished, visually striking user interface (e.g., a beautifully designed mobile app, a dashboard with custom data visualizations, a landing page with unique animations).
- You can extract standalone screenshots or mockups that look good in isolation (e.g., a login screen, a profile card, a settings panel).
- The project's value is immediately apparent from a single image or a short looping GIF (e.g., a weather app with gorgeous iconography, a fitness tracker with a clean chart layout).
- Your project follows current design trends (glassmorphism, neumorphism, minimalism, vibrant gradients) and aligns with Apple/Human Interface Guidelines aesthetics.
- You are seeking freelance clients, design job opportunities, or brand visibility rather than technical feedback or developer contributions.

## Poor Fit

- Your project is purely backend or infrastructure (e.g., a database engine, a CI/CD tool, a CLI utility) with no visual interface.
- The project's main value is in code quality, performance benchmarks, or algorithmic innovation (e.g., a new sorting algorithm, a compression library).
- Your project is a text-heavy resource (e.g., a documentation site, a technical blog, a wiki) with minimal visual design.
- The project is in early alpha with placeholder UI, broken layouts, or low-resolution assets.
- You are looking for constructive technical criticism, deep architectural discussions, or code reviews — Dribbble is not a developer forum.

## Format And Style Notes

- Lead with the hero shot. The first image must be the strongest, most visually complete screen. Never post a wireframe, a low-fidelity sketch, or a blank canvas as the hero.
- Keep descriptions under 3 sentences. State what the project is and one key design choice. No backstory, no technical specs.
- Use 3-5 relevant tags. Tags are the primary discovery mechanism. Always include format tags (e.g., #UI, #Dashboard) and tool tags (e.g., #Figma, #Sketch).
- Show multiple states, not multiple angles. Use attachments to display variations: empty state, loading state, error state, dark/light mode, or responsive breakpoints.
- Animate the hero shot if possible. Looping GIFs (exported as MP4) get significantly more engagement than static images. Focus on micro-interactions: hover states, loading spinners, card flips.
- Avoid text on the image unless it's part of the UI. Do not overlay your logo, watermark, or "Copyright 2025" text on the image. Let the design speak for itself.
- Use consistent, trendy color palettes. Dribbble rewards designs that feel current. Research trending palettes on the platform before posting.
- Tag the tools you used in the description. Mentioning Figma, Sketch, or Adobe XD increases credibility and searchability.

## Tone

Every shot is a billboard for your design taste — make it beautiful, make it trendy, and let the image do all the talking.
