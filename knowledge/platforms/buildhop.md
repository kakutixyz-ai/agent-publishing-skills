## Trigger Context

Triggered by mentions of 'BuildHop', 'builder community', 'project showcase', or 'maker directory'

## Language

**Primary language:** English (American English). The platform serves a global audience of builders, makers, and indie developers, all of whom communicate in English. Content in other languages is rare and will significantly reduce reach. If your project has non-English documentation, include a brief English summary and link to the localized version.

## Good Fit

- A shippable, functional product (web app, mobile app, CLI tool, library, design system) with a working demo or live URL.
- A side project or bootstrap startup that solves a specific problem for developers, designers, or small teams.
- A developer tool (API wrapper, code generator, testing framework, deployment helper) that other builders can immediately use.
- A design resource (icon set, UI kit, component library, Figma plugin) that accelerates product creation.
- A well-documented open-source project with a clear README, contribution guide, and a live demo or screenshot.

## Poor Fit

- A landing page or pre-launch teaser with no working product behind it.
- A content site, blog, or newsletter — BuildHop is for products, not publications.
- A consulting agency or service offering (e.g., "We build apps for clients").
- A crypto/NFT/gamefi project unless it is a genuine developer tool; pure speculation projects are unwelcome.
- A low-effort submission with no description, broken links, or placeholder text.

## Format And Style Notes

- Lead with a clear headline — the product name only. Do not add taglines, emojis, or hype words in the title.
- Write a one-paragraph summary (2–3 sentences) that states the problem and solution.
- Use bullet points for key features only (3–5 max). Keep each point to a single line.
- Include exactly one call-to-action link — the project's homepage or GitHub repo.
- Avoid emojis, exclamation marks, and marketing superlatives.
- Use technical language appropriate for a builder audience. Be precise, not vague.
- Do not mention upvotes, launches, or community rankings. Let the product speak.
- End with a short, neutral closing line — no calls to action beyond the link.
