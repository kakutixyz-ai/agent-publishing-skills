## Language

- **Primary Language:** English (international standard). While the company is based in Spain, the entire site, jury, and community operate in English.
- **Multilingual Strategy:** Spanish is acceptable only for localized Spanish agencies submitting to a Spanish jury. For global visibility, English is required. Non-English submissions receive significantly lower engagement and are not considered for international awards.
- **Tone Requirements:** Technical, precise, and jargon-rich. Use terms like "viewport units," "critical CSS," "lazy loading," "cubic-bezier curves," "custom properties," and "CLS score." Avoid marketing fluff or emotional language. Be direct: "The micro-interaction on the CTA button reduces friction" (not "This button is beautiful").

## Good Fit

- High-fidelity, visually-driven websites with custom animations (GSAP, Three.js, WebGL), unique layouts, and innovative UI patterns.
- Agency portfolio sites showcasing client work with detailed case studies, performance metrics, and before/after comparisons.
- Creative tools or libraries that produce visually stunning output (e.g., a WebGL particle generator, a CSS animation framework, a typography tool).
- Accessibility-forward projects that balance aesthetics with WCAG compliance, ARIA labeling, and keyboard navigation.
- Performance-optimized web experiences with sub-2s load times, lazy loading, and responsive design across all viewports.

## Poor Fit

- Standard SaaS dashboards or admin panels with minimal visual design (e.g., CRM tools, analytics dashboards, project management UIs).
- Content-heavy blogs or news sites where text readability is the primary feature (e.g., Medium clones, WordPress blogs).
- Backend-only libraries or APIs with no visual interface (e.g., authentication packages, database drivers, CLI tools).
- Mobile apps that are not responsive web experiences (Awwwards judges web design, not native mobile apps).
- Low-effort, template-based sites using off-the-shelf themes with no custom code or original design thinking.

## Format And Style Notes

- Use technical, data-backed critiques, not emotional praise.
- Describe the problem, the technical solution, and the measurable result.
- Use specific CSS/JS terminology in descriptions.
- Critique with a score implication — always tie feedback to the voting criteria.
- Keep comments to one short paragraph — no Markdown, no emojis, no decorative formatting.
- Include mobile-specific observations in every critique.
- Reference specific performance metrics (Lighthouse, Web Vitals) when possible.
- Use tags that specify technology stack, not generic categories.

## Tone

Awwwards is a high-stakes, technical gallery where pixel-perfection, performance optimization, and original UX design are judged with professional rigor — every submission must prove it belongs among the best web work in the world.
