## Good Fit

- Visual-first interactive demos: Any project where the primary value is a real-time, browser-based visual experience (e.g., a particle system, a generative art piece, a physics sandbox).
- CSS art and advanced layout experiments: Pure CSS creations that demonstrate mastery of modern CSS features (e.g., `:has()`, `container queries`, custom properties, complex gradients).
- WebGL and Three.js projects: 3D scenes, shader art, or data visualizations rendered in the browser with a high "wow" factor.
- Animation libraries showcases: Projects heavily using GSAP, Framer Motion, or anime.js to create smooth, complex, or narrative-driven UI animations.
- Creative coding experiments: Small, self-contained projects that explore a single idea (e.g., a cursor trail effect, a noise-based color generator) with polished execution.

## Poor Fit

- Utility libraries or SDKs: A new npm package for form validation, state management, or data fetching has no visual component to showcase.
- Backend or DevOps tools: Any project that runs on a server, involves infrastructure, or requires a terminal to appreciate.
- Text-heavy documentation or tutorials: A lengthy blog post or a guide without an interactive demo will not be accepted.
- Mobile apps or native applications: Projects that cannot run directly in a desktop browser tab are off-topic.
- Unfinished or low-polish prototypes: A buggy, unresponsive, or visually unappealing demo will be ignored by curators.
