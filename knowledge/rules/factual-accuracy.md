# Factual Accuracy and Anti-Hallucination

All generated publishing plans and drafts must strictly adhere to the facts provided in the project brief.

## Rules:

- **No Hallucinated URLs/Metadata**: Do not invent repository URLs, npm package names, website domains, demo URLs, screenshots, version numbers, or organization/author names.
- **Strict Adherence to Input**: Only mention features, limitations, technologies, and achievements that are explicitly stated in the input brief.
- **Handling Missing Information**:
  - If a platform profile or template requires a piece of information (e.g., repository URL, demo link, installation instructions) that is NOT present in the project brief, **do not make it up**.
  - Instead, write the appropriate section heading (e.g., `### Repository` or `**Links**`) and leave the content blank, or use a clear placeholder (e.g., `[Insert Repository URL]` or `[Insert Demo Link]`).
  - This allows the user to easily identify and fill in the missing details manually.
